# AtmoViz

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23326027.svg)](https://doi.org/10.5281/zenodo.23326027)
[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](LICENSE)

A browser-based tool for exploring **geolocated environmental measurements**
recorded while moving through a place: temperature, humidity, pressure, VOC,
particulate matter (PM1, PM2.5, PM10), an air-quality score and the derived dew
point. Load a route, replay it on a map, judge every reading against health
thresholds that depend on who is breathing the air, and export a report.

**Live demo:** <https://grazianoenzomarchesani.github.io/AtmoViz/> — deployed to
GitHub Pages on every push to `main`.

Everything runs in the browser. Your data files and photos are never uploaded
anywhere (see [Network access](#network-access) for the two things that do
reach the network).

## What it does

- **Route playback.** The measurements are drawn on a map as a path, as points
  or as a heatmap, coloured by the selected metric. A timeline lets you scrub or
  play the route back at speeds from 1× to 50×, with a compact class band under the
  curve showing the quality class over time.
- **Risk profiles ("personas").** Each reading is classified against thresholds
  for a *standard* adult, an *asthmatic* person, a *child* or an *athlete*.
  Colours, labels and descriptions follow the selected profile, and a reference
  guide lists the ranges together with practical advice (ventilation, filtration,
  source control).
- **Filters and statistics.** Restrict the analysis to a time window, hide
  points without GPS, keep only complete rows; open the statistics view for
  per-metric min / mean / max.
- **Thermal photo layer.** Drop in geotagged photos (including FLIR thermal
  images); those with EXIF GPS are placed on the map as a toggleable layer, with
  camera model and capture time in the preview.
- **PDF report.** Map snapshot, one trend chart per metric and a min / mean / max
  table, optionally with a written summary generated by Gemini (see
  [Optional AI summary](#optional-ai-summary)).
- **Light and dark themes**, with a dark variant of the base map, and a guided
  tour of the interface.

## Input data

Data is loaded from the *Load data* dialog, in three independent steps.

| Step | Files | Content |
|---|---|---|
| GPS route | `.csv`, `.xlsx`, `.xls` | One row per sample. Only `Date` is required. |
| Sensor readings | `.csv`, `.xlsx`, `.xls` | Extra readings aligned in time to an already-loaded route. |
| Photos | images with EXIF GPS | Placed on the map; photos without GPS are skipped. |

The CSV columns recognised for the route are:

```
Date, VOC, ppm, AQS, Temperature, °C, Humidity, %, Pressure, mbar,
PM1, ug/m3, PM2.5, ug/m3, PM10, ug/m3, Latitude, Longitude
```

(i.e. the headers `Date`, `VOC, ppm`, `AQS`, `Temperature, °C`, `Humidity, %`,
`Pressure, mbar`, `PM1, ug/m3`, `PM2.5, ug/m3`, `PM10, ug/m3`, `Latitude`,
`Longitude`). Dates may be ISO strings, Excel serial dates, or the European
`dd/mm/yyyy hh:mm:ss` format. Missing values are allowed.

## Run it locally

Requires Node.js 20 or newer.

```bash
npm install
npm run dev        # http://localhost:3000
```

Other scripts:

```bash
npm run build      # production build in dist/
npm run preview    # serve the production build
npm run check:map  # validate the light and dark map styles and their fonts
```

`base` in `vite.config.ts` is `/AtmoViz/`, matching the GitHub Pages project
path. Change it if you serve the build from somewhere else.

## Network access

Nothing you load leaves the browser, no cookies are set and nothing is written to
browser storage. The in-app **Privacy notice** (shield icon, or the link on the
start screen) spells out what each service below can see. The page does contact:

- **OpenFreeMap** (`tiles.openfreemap.org`) for the base-map vector tiles and
  fonts. No account or API key is needed.
- **Google Fonts** and the **Tailwind CDN**, loaded from `index.html`, for
  typography and styling.
- **Google's Gemini API**, only if you build with an API key and generate a
  report (below).

### Optional AI summary

The PDF report can include an executive summary written by Gemini. This is off
unless a key is provided at build time:

```bash
echo "GEMINI_API_KEY=your-key" > .env.local
npm run dev
```

Vite inlines the key into the JavaScript bundle, so **do not publish a build
made with a key you care about**. The public demo is built without one, and
reports are produced with statistics only. When a key is present, the computed
statistics and the persona thresholds (not your raw files) are sent to Gemini.

## Base map

The base map is a MapLibre GL rendering of the *Toner* look (Stamen Design, in
the MapTiler/OpenMapTiles GL implementation, BSD-3-Clause — see
[`utils/toner-style.LICENSE.md`](utils/toner-style.LICENSE.md)) on OpenFreeMap
tiles, with map data © OpenStreetMap contributors.

## Project layout

```
App.tsx            application state and layout
components/        map board, timeline, control bar, filters, statistics,
                   photo layer, reference guide, report modal, tour
utils/             CSV/Excel parsing and persona thresholds (dataUtils),
                   EXIF reading, base-map style builder, Toner style JSON
scripts/           map style validation (npm run check:map)
public/map/        map sprites
```
